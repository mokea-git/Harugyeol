Repository Guidelines

Coding conventions, build commands, and contribution rules for Harugyeol

Project Structure & Module Organization

This repository is a small monorepo with two active apps:

  • haru_app/ — Flutter client (lib/core for shared infra, lib/features for feature modules)
  • harugyeol-server/ — Fastify + TypeScript API (src/routes, src/middleware, src/lib)
  • docs/ — product and architecture context
  • assets/ — shared design assets

Keep feature-specific code inside each app's feature folder; avoid cross-app imports.

Build, Test & Dev Commands

Client (haru_app)

flutter pub get    # install dependencies
flutter run        # launch in debug
flutter analyze    # static analysis
flutter test       # run tests

Server (harugyeol-server)

npm ci             # install from lockfile
npm run dev        # run with ts-node-dev
npm run build      # compile TypeScript → dist/
npm run start      # run compiled server

Coding Style & Naming

언어규칙
Dartflutter_lints 준수 · 2-space · snake_case.dart 파일명 · PascalCase 클래스
TypeScriptstrict mode · 2-space · camelCase 변수/함수 · PascalCase 타입
  • Route handler는 얇게, 공유 로직은 src/lib으로 분리
  • Auth: Supabase는 OAuth sign-in/token 검증에만 사용, DB 쓰기 금지
  • 프로필 데이터 (image, name, email)는 서버 SQLite에 저장

Testing Guidelines

  • Flutter: haru_app/test/ 에 *_test.dart 형식으로 작성
  • UI 상태·라우팅·API 연동 변경 시 테스트 추가/업데이트
  • 서버: 공식 테스트 없음 — npm run build 후 주요 엔드포인트 smoke-test

Commit & PR Guidelines

Conventional Commits 형식 준수 (feat:, fix:, chore:), 한국어 요약 포함.

PR 포함 항목:

  • 변경 범위 요약
  • 연결된 이슈/태스크
  • 테스트 증거 (출력 또는 스크린샷)
  • 환경 설정 변경 사항 (.env, API 키, 마이그레이션)

Security & Configuration

실제 시크릿을 절대 커밋하지 마세요. .env.example을 템플릿으로 사용하세요.
